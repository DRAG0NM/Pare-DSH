# Pare-DSH 开发计划

> 当前为实施路线草案。插件实现依赖 Pare Core 的稳定 CLI schema 和 DSH 接入能力核验。

## 阶段 0：宿主和接口核验

- 取得 DSH 官方 SDK/插件文档，记录工具注册、stdio/sidecar、权限与审批能力。
- 从 Pare 仓库选定 `pare.scan/1` 与 `pare.plan/1` 的正式输入输出 schema。
- 明确插件允许的核心二进制分发方式。
- 验收：有可执行的最小 host fixture；不再以未验证的 SDK 能力作为设计前提。

## 阶段 1：只读插件原型

- 建立最小插件包和 `disk_scan`、`disk_plan` 两个只读工具。
- 以参数数组启动固定路径的 Pare CLI，设置超时、取消和输出上限。
- 校验 schema、版本和退出码，返回摘要及本地报告引用。
- 验收：无核心、版本不符、非法 JSON、部分失败和超时都有可辨识响应；不接受任意路径或命令。

## 阶段 2：固定核心分发

- 选择随包附带或固定版本下载方案。
- 加入 SHA-256 校验、schema 兼容范围和可重复发布流程。
- 验收：核心文件被改动或版本不兼容时，插件拒绝执行；安装不携带用户扫描数据。

## 阶段 3：宿主集成和隐私审查

- 使用 DSH host fixture 做调用、输出大小、取消、超时和权限声明集成测试。
- 检查用户名、目录路径和软件清单的最小化策略。
- 验收：响应不泄漏整份文件清单；用户能查看本地完整结果和扫描缺口。

## 阶段 4：评估写工具（单独立项）

- 只有审批信号能绑定计划摘要、选择、动作、有效期和单次执行时，才起草 apply/undo 设计。
- 对接 Pare Core executor 的受控 plan ID 接口，不把裸路径传给核心。
- 验收：审批被取消、过期、摘要不匹配、ID 被替换或核心版本不兼容时均拒绝；执行细节另设安全测试集。

## 阶段 5：发布

- 选定插件包格式、支持的 DSH 版本、核心兼容矩阵和许可证。
- 发布工具 schema、校验和来源清单；不自动上报扫描内容。
- 验收：干净环境安装、版本升级/降级、离线读取现有报告均经过验证。
